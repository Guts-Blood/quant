## 优先级与验收

### 1. 首先交付一段可对账的股票执行数据

- 从一段历史中证 500 成分完整、能查到公司行动原件的时期开始，连同信号预热期、持仓期及期间调出股票一起覆盖。按交易日和六位股票代码生成 `execution.parquet`。对齐复权收益、可交易状态、涨跌停价或豁免、公司行动、每股现金分红及支付日。原始价用于成交和估值，复权序列用于计算收益和因子。
- 固定来源版本、复权方式和单位。按日列出应有证券数、实有数、重复键及缺失原因。抽查除息、停牌、涨跌停和成分调出的日期，对账现金、股数与净值。未知公司行动保留原因；涉及持仓时，将受影响回放标为不可用。
- **验收**：主键唯一，连接行情、估值和成员表后无重复放大，所有必需缺口可定位。用真实面板跑出同一窗口的候选、订单、成交或拒单、持仓、费用与净值。按日对上现金和持仓市值，再扩大年份覆盖。[执行表字段和基线入口](MARKET_RESEARCH.md)

### 2. 与执行表并行，积累 510500 的固定时点 IV30

- 每个交易日按上海时间 15:01 留下整批原始响应、合约买卖价、报价时刻、到期日、调整标记及利率假设。保存采集失败和重试记录，盘中与固定时点单独存放。
- 每日核对应收／实收合约数、报价年龄、有效双边数、近远月两翼行权价和缺值原因。历史供应商先用一小段原始数据试算，确认能还原同一观察点，再决定是否扩充长历史。
- **验收**：另一环境可从归档报价复算每一天的值或缺值原因。仓位实验还要求过去 252 个交易日至少有 126 个有效固定时点值、信号当日有值，且下一交易日有可成交和估值的股票数据。单独报告有效信号日、触发日和共同可调仓日。[采集与回放规则](MARKET_RESEARCH.md) · [冻结参数](../configs/market-data/value-lowvol-iv30.json)

### 3. 建设盈利质量和反向 DCF 共用的历史财报层

- 每个财务值保存证券、字段、报告期、公告时间、可用时间、采集时间、修订号、单位和来源。同一历史信号只读取截止时点已可用的版本。只有公告日期时，采用明确的保守生效规则并保留时间精度。
- 第一批覆盖净利润、经营现金流、总资产，区分单季、年内累计和过去四季。DCF 先做少量非金融候选，补当时股本、债务、现金、少数股东权益、非经营资产、收入与经营利润。利润率路径、再投资效率、折现率和终值假设单列来源或估计依据。
- **验收**：对一份有修订的财报，能复现修订前后的两个决策截面。对一家公司，能从原报表对至经营企业价值，复算隐含增长与压力情景。缺资料、无解和多解分别记录。单列候选覆盖率，供实验判断样本偏差。[历史时点接口](RESEARCH.md) · [DCF 附注入口](../experiments/shortlist_dcf.py)

### 4. 让下一次云端运行能复核结果

沿用现有 Git 代码、版本清单、Drive 数据分卷和研究回执。每次扩充数据都发布子版本，写清新增日期、字段、已知缺口和原始文件哈希。成交日对照、同口径中证 500 全收益基准、历史行业和规模暴露随研究窗口一起留档。

**交接验收**：新 session 按发布说明恢复同一版本，校验清单和数据哈希，重跑固定成交验收及相应研究窗口。比对候选、委托和日净值；若当期无法运行，回执应给出一致的阻塞原因。[恢复与归档步骤](MARKET_RESEARCH.md) · [团队数据目录](https://drive.google.com/drive/folders/1WG-gCvQdpq17iSszhUAre3vFVK2dF_GF)
